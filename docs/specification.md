
# hapmap.app specifications

> This document is Authored by Bill. Agents use this as a source of design ideals for the website. Agents do not make edits to this document except very concise edits where explicitly requested to by Bill. 

Hapmap.app is an interface for exploring and qualitatively interpreting Austrlaia's historical aerial photography 

- The prototype version of the site covers Canberra and the wider ACT.
- The subtitle of the site is 'Exploring Australia's historical aerial photography'
- The site's favicon is a minimalist vector representation of an oblique view of an aeroplane in flight that shows a view-cone coming out of the bottom of the plane. 

## Technical stack

- The site uses Map Libre
- Mosaics are stored as Cloud Optimised Geotiffs (COGs) in an R2 bucket
- The browser calculates the request arrays for the COGs

## Data

### Provenance

- Historical aerial photography frames are stitched together primarily using the [blag map](https://github.com/ANUcybernetics/blag-map) method. 
- Most data is sourced from the Geoscience Australia collection.
- Some layers are derived from full photogrammetric resconstruction of the same data. 
- (almost) All layers are automatically georeferenced to modern satellite reference images using computer vision techniques.

### STAC

- Mosaics generated for the project are stored in a [Spatio-Temporal Asset Catalogue (STAC)](https://github.com/radiantearth/stac-spec).
- Each mosaic in the STAC is given a UID and a descriptive name.
- The stac holds metadata about the provenance and composition of each mosaic in the form of a raster that attributes each pixel to an originating frame. 
- The layer list is routinely procedurally generated from the STAC catalogue.
- Geotiffs have all of the data from their STAC listing as attached metadata.
- The processing pipeline ends by uploading a new layer to R2 which is then automatically added to the STAC. 
- For any blagmap generated mosaic, the STAC entry reports which version of the software was used to generate the mosaic.
- For any blagmap generated mosaic, the STAC entry reports the command used to generate the mosaic (showing which flags were used).

### Licencing

- GA provides historical frames under Creative Commons attribution licences. 
- Older frames have entered the public domian.
- All mosaics generated by the hapmap project are released as CC-by 4.0

## Interface

- We try to minimise screen real-estate used by overlays/tools. The interface is intended to be a map and nothing more. 

### Left click
 - Clicking on the image mosaics queries the provenance raster for the currently visible layer. It shows a small popup which queries GA's servers to display a preview of the frame that contributed the clicked pixel.
- The preview popup includes a link to download the full resolution version of the image. 
- Clicking the preview image opens the preview image in a new tab.
- There is not a button in the popup window that allows the user to overlay the tiepoints that located the preview image on the map. Tiepoints are never shown.

### Atrribution

- A concise attribution statement is shown at the bottom of the page for the layer displayed on screen.
- The attribution statement only describes the currently visible layers. 
- For each of the layers generated by the hapmap project, the attribution statement includes a hyperlink to the mosaic's listing in the STAC.

### Search

- A search box at the top allows users to search for a modern-day address and pan the map to that place. 
- This uses Nominatim API and a MapLibre standard plugin.

### Pan and Zoom

- An unobtrusive `Loading...` overlay is displayed whenever data is being fetched.
- A subtle visual cue informs the user when they are over-zooming a layer. 

### Layers

- Each layer represents a year (or epoch)
- Different layers have different extents.
- One layer is displayed at a time.
- The default layer is OSM tiles. These are displayed wherever the currently selcted layer does not cover. 

### Timeline

- The timeline is shown on the right of the page and is always visible regardless of viewport. 
- Some years have no layer.
- At most, one layer per year.
- Where a layer's source material was collected over multiple years, the midpoint of the range of dates is used as the definitive date. 
- The timeline uses a subtle visual cue (greying out layers with no coverage) to distinguish which of the epochs have coverage interescting the current extent of the map. 
- Similarly, layers that have coverage of the current extent, but at a coarser resolution than the current zoom, are shown with a subtle visual cue that distingueshes them from layers with good quality coverage of the current map extent.
